# DevBareun v1.4.12 Package Completeness Audit

This release closes the overly aggressive clean-package gap found after v1.4.11.

## What was re-checked

The clean package was compared against the original `devbareun_full_v1.4.0_latest` archive by normalized path, while still excluding generated/dependency folders that should not be shipped:

- `.venv/`
- `node_modules/`
- `.git/`
- `dist/` and `build/`
- `__pycache__/` and test/cache folders
- runtime `.env` files

## Important finding

The previous clean package restored `frontend/assets/`, but it still did not include the built static workspace under:

```text
frontend/workspace/
```

This directory is needed by `frontend/vercel.json` rewrites such as `/workspace/* -> /workspace/index.html` when the frontend is deployed as a static surface.

## Fix

The v1.4.12 package includes a freshly built workspace generated by:

```bash
cd frontend
npm run build
```

The package now includes:

```text
frontend/workspace/index.html
frontend/workspace/assets/*.js
frontend/workspace/assets/*.css
frontend/workspace/assets/favicon.*
frontend/workspace/assets/devbareun-*.svg
```

## New release checks

New tool:

```bash
python tools/check_frontend_deploy_surface.py --root . --strict
```

Existing template validation tool is also included in the package and CI:

```bash
python tools/check_template_manifest.py --root .
```

These checks prevent future packages from shipping with logos/templates present but the deployable workspace missing.

## Remaining intentionally excluded items

The original archive contains development/runtime material that remains intentionally excluded:

```text
.venv/
node_modules/
.git/
dist/
build/
__pycache__/
.pytest_cache/
```

The original archive also contained `artifacts/devbareun-customer-panel-current.png`, which is a generated audit/screenshot artifact rather than an application runtime file. It is not required for deploy.
